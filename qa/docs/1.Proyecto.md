# Proyecto: Sistema de Gestión de Incidentes OpsCore

## Descripción del proyecto

OpsCore está digitalizando las operaciones de una planta industrial con 400 operarios. Actualmente, cuando ocurre una falla de máquina, un accidente o una desviación de calidad, se registra en papel o mediante WhatsApp. Esto provoca falta de trazabilidad, tiempos de respuesta no medidos y recurrencia de las causas raíz porque no existe un aprendizaje sistemático.

El objetivo del proyecto es desarrollar un sistema de gestión de incidentes que permita reportar fallas desde cualquier dispositivo, hacer el seguimiento de la resolución y analizar causas raíz recurrentes para reducir la frecuencia de incidentes críticos.

## Expectativas del sistema

- Formulario de reporte optimizado para dispositivos móviles, accesible desde el celular del operario.
- Panel de monitoreo con estados de incidentes: abiertos, en proceso y cerrados.
- Módulo de análisis de causas raíz con clasificación por tipo y por área.
- Métricas de tiempo de respuesta y tasa de resolución por período.

## Usuarios

- **Operario**: reporta un incidente desde la línea de producción.
- **Supervisor**: asigna responsabilidades y monitorea el avance.
- **Gerente de planta**: analiza patrones y causas raíz recurrentes.

## Flujo de trabajo

1. El operario detecta una falla.
2. Abre el formulario desde su teléfono móvil.
3. Completa el tipo de incidente, el área afectada y una breve descripción.
4. Envía el reporte.
5. El supervisor recibe la alerta.
6. El supervisor asigna un técnico responsable.
7. El técnico resuelve el incidente y cierra el reporte con la solución aplicada.
8. El sistema registra el tiempo de resolución.
9. El gerente revisa semanalmente el análisis de causas raíz e identifica patrones recurrentes.

## Requerimientos

### Requerimientos funcionales

- RF1: El sistema debe permitir a los operarios registrar incidentes desde un formulario móvil.
- RF2: El formulario debe permitir seleccionar el tipo de incidente, el área y una descripción breve.
- RF3: El sistema debe mostrar un dashboard con los incidentes abiertos, en proceso y cerrados.
- RF4: El supervisor debe poder asignar un técnico responsable a cada incidente.
- RF5: El técnico debe poder cerrar un incidente indicando la solución aplicada.
- RF6: El sistema debe calcular y registrar el tiempo de respuesta y de resolución de cada incidente.
- RF7: El sistema debe ofrecer un módulo de análisis de causas raíz.
- RF8: El análisis debe permitir clasificar incidentes por tipo y por área.
- RF9: El gerente debe poder consultar métricas de resolución por períodos.

### Requerimientos no funcionales

- RNF1: La interfaz de reporte debe ser responsiva y optimizada para dispositivos móviles.
- RNF2: El sistema debe ser accesible desde celulares y navegadores modernos.
- RNF3: La información debe ser almacenada de forma segura y trazable.
- RNF4: El tiempo de carga de la vista de dashboard debe ser razonable para el usuario.
- RNF5: El sistema debe permitir la generación de métricas y reportes de forma clara.

## Entregables esperados

- Documento de requerimientos en español.
- Formulario móvil para registro de incidentes.
- Dashboard de monitoreo con estados de incidentes.
- Módulo de análisis de causas raíz.
- Métricas de tiempo de respuesta y tasa de resolución.

## Notas adicionales

- El proyecto se enfocará en resolver la falta de trazabilidad y la recurrente aparición de incidentes críticos.
- El sistema debe facilitar el aprendizaje y mejora continua en la operación de la planta.
